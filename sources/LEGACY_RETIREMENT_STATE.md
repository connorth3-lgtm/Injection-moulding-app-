# Legacy runtime retirement state

Reviewed: 2 September 2026

This file is the fail-closed retirement decision for historical MouldMaster runtime lanes. It does not treat a legacy asset as removable merely because the current browser or Electron application passes automated QA.

## GitHub Pages legacy publisher

State: **retired / absent from branch inventory**.

The repository branch inventory reviewed on 2 September 2026 contains no `gh-pages` branch. The supported public-site publisher is `.github/workflows/pages.yml`, which builds the allowlisted Pages artifact, deploys it, and verifies the live deployment. Release QA must continue to fail if a `gh-pages` branch is reintroduced, because that would recreate a competing publication lane.

This statement is repository-scoped. It does not claim that GitHub has no historical deployment records; it asserts that there is no current `gh-pages` source branch and that MouldMaster must retain one supported Pages publication path.

## Frozen Windows recovery launcher

Asset: `MouldMasterAcademy.exe`  
State: **retained — retirement blocked by required real-Windows evidence**.

The executable remains a recovery lane until every retirement checkbox in `desktop/electron/REAL_WINDOWS_VALIDATION.md` has been completed on a normal Windows 10/11 environment using a verified current desktop release and a real legacy progress backup. GitHub-hosted CI is not a substitute for that exercise.

Retirement prerequisites are:

- published executable SHA-256 independently matches its release checksum;
- normal Windows launch passes;
- local learner state survives close/reopen and a Windows restart;
- offline launch works after the first successful launch;
- a real legacy progress backup imports with the expected profile, progress, notes and history;
- imported certificate/pass state is not trusted as current completion authority;
- keyboard/navigation smoke checks pass;
- the evidence is retained outside the public repository under appropriate privacy controls.

Until an explicit non-sensitive retirement evidence marker is added to this repository, release QA must require `MouldMasterAcademy.exe` to remain present and must reject any claim that Windows recovery retirement is complete.

## Compatibility loader

Asset: `MouldMaster_Academy_App.html`  
State: **retained — compatibility dependency**.

The current service-worker and Electron packaging/integrity checks still include this compatibility loader. It must not be deleted independently of the Windows migration/retirement change. When the Windows retirement evidence exists, the retirement PR must either remove this compatibility dependency safely or document why it remains necessary and keep it within the integrity/deployment gates.

## Retirement evidence marker

The future retirement PR must add `data/legacy-windows-retirement-evidence.json` containing only non-sensitive evidence metadata. At minimum it must include:

- `schema: 1`;
- `status: "approved-for-retirement"`;
- the tested MouldMaster desktop release and executable SHA-256;
- the Windows 10/11 version used;
- boolean pass fields for launch, persistence, restart persistence, offline launch, real-backup import, certificate-state rejection and keyboard/navigation smoke testing;
- `content_copied_to_evidence: false`;
- a review date and reviewer label that do not contain learner or customer information.

The marker is not generated by CI. It may only be created after the real-machine procedure is completed. Once the marker exists and validates, QA must invert: the recovery executable may no longer remain in the release source tree, so the retirement PR cannot stop halfway.

## Canonical-runtime consolidation

The assessment manifest introduced by this hardening wave is the canonical machine-readable representation of the current learner assessment surface, but it does not yet replace the monolithic core HTML or every runtime overlay. Removing all historical overlay layers and eliminating the CSP requirement for inline script/style are separate architectural migrations. They must be performed incrementally with exact-head browser/PWA/desktop QA rather than by deleting compatibility code in this retirement change.
